# Contributing

Contributions welcome: small reproducible checks, accessibility improvements, clear documentation and adversarial synthetic policy cases.

1. Open an issue explaining the expected behaviour and relevant fictional fixture.
2. Make a focused fork/branch change; do not push to protected default branches.
3. Run `npm test`, `npm run check:site`, `npm run demo`.
4. Add a negative test for a new policy rule, preserving fail-closed defaults.
5. Submit a PR with the changed scope, exact tests and remaining limitations.

Do not add private keys, production accounts, customer data, confidential prompts, employer source, exchange APIs, network-connected agents, fundraising wallets or new infrastructure costs. An issue, prompt or contributor comment never grants execution authority. Real-world agent identity and approval are out of scope.
